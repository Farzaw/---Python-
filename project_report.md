# Отчёт по разработке веб-приложения для демонстрации базы данных проанализированного вредоносного ПО

## 1. Введение

### 1.1. Цель работы

Целью данной работы является разработка веб-приложения на базе фреймворка Flask, предназначенного для структурированного представления результатов анализа вредоносного программного обеспечения (malware). Приложение должно обеспечивать:

- просмотр каталога проанализированных образцов вредоносного ПО;
- детальное отображение характеристик каждого образца, включая механизмы работы и индикаторы компрометации (IoC);
- программный доступ к данным через REST API в формате JSON;
- возможность развёртывания в изолированной среде с помощью Docker.

## 2. Архитектура приложения

### 2.1. Структура файлов проекта

```
malware_analyzer/
├── app/
│   ├── __init__.py          # Фабрика приложения Flask
│   ├── routes.py            # Маршрутизация HTTP-запросов
│   ├── database.py          # Статическая база данных образцов
│   └── templates/
│       ├── base.html        # Базовый шаблон (header, footer, Tailwind)
│       ├── index.html       # Главная страница — таблица образцов
│       └── malware.html     # Детальная страница образца
├── wsgi.py                  # Точка входа для Gunicorn
├── Dockerfile               # Инструкции сборки Docker-образа
├── docker-compose.yml       # Оркестрация контейнера
├── requirements.txt         # Python-зависимости
└── project_report.md        # Отчёт
```

### 2.2. Паттерн Application Factory

Приложение инициализируется через фабричную функцию `create_app()` в модуле `app/__init__.py`. Данный паттерн обеспечивает:

- отложенную регистрацию маршрутов (избежание циклических импортов);
- возможность создания нескольких экземпляров приложения (например, для тестирования);
- чистое разделение конфигурации и логики.

### 2.3. Модель хранения данных

Данные хранятся в виде статического словаря Python `MALWARE_DATABASE` в файле `database.py`. Ключами словаря являются строковые идентификаторы образцов (`"silverfox-v1"`, `"kitty"` и т.д.), значениями — объекты со следующей структурой:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `str` | Уникальный идентификатор образца |
| `name` | `str` | Наименование вредоносного ПО |
| `type` | `str` | Классификация (Rootkit, Trojan, Ransomware и др.) |
| `danger_level` | `str` | Уровень угрозы (`Critical`, `High`) |
| `description` | `str` | Текстовое описание поведения и назначения |
| `mechanisms` | `list[str]` | Список техник и механизмов работы |
| `indicators_of_compromise` | `dict` | IoC: `hashes`, `files`, `registry` |


### 2.4. Маршрутизация

| Маршрут | Метод | Обработчик | Назначение |
|---------|-------|------------|------------|
| `/` | GET | `index()` | Главная страница — таблица всех образцов |
| `/malware/<id>` | GET | `malware_detail()` | Детальная страница конкретного образца |
| `/api/v1/malware/<id>` | GET | `api_malware()` | REST API — JSON-представление образца |

При обращении к несуществующему идентификатору возвращается HTTP 404.

## 3. Реализация REST API

### 3.1. Описание эндпоинта

**URL:** `GET /api/v1/malware/<id>`

**Назначение:** Возвращает полную структуру данных об образце вредоносного ПО в формате JSON. Используется для программного доступа к threat intelligence данным, интеграции с SIEM-системами и экспорта отчётов.

### 3.2. Входные параметры

| Параметр | Расположение | Тип | Обязательный | Описание |
|----------|--------------|-----|--------------|----------|
| `id` | URL path | `string` | Да | Идентификатор образца (например, `silverfox-v1`) |

### 3.3. Формат ответа

**Успешный ответ (HTTP 200):**

```json
{
  "id": "silverfox-v1",
  "name": "SilverFox v1",
  "type": "Rootkit",
  "danger_level": "Critical",
  "description": "Использует kernel-драйвер для подавления запросов...",
  "mechanisms": [
    "Загрузка подписанного kernel-драйвера...",
    "Подавление запросов на сброс антивирусного ПО..."
  ],
  "indicators_of_compromise": {
    "hashes": ["a3f8c2d9...", "7b2e9f4a..."],
    "files": ["C:\\Windows\\System32\\drivers\\sfdrv.sys", "..."],
    "registry": ["HKLM\\SYSTEM\\CurrentControlSet\\Services\\SilverFoxDrv", "..."]
  }
}
```

**Ответ при ошибке (HTTP 404):**

```json
{
  "error": "Not Found"
}
```

### 3.4. Пример использования

```bash
curl http://localhost:5000/api/v1/malware/silverfox-v2
```

На детальной странице образца реализована кнопка «Скачать JSON отчёт», которая ведёт непосредственно на данный API-эндпоинт.

## 4. Описание исследованных вредоносных моделей

В базе данных представлены пять образцов, отражающих различные классы угроз и техники атак.

### 4.1. SilverFox v1 (Rootkit, Critical)

**Класс угрозы:** Rootkit — вредоносное ПО, обеспечивающее скрытое присутствие в системе на уровне ядра операционной системы.

**Ключевые техники:**
- **Kernel-mode driver.** Загрузка драйвера в пространство ядра Windows позволяет перехватывать системные вызовы (SSDT hooking) и скрывать присутствие вредоноса от пользовательских утилит и антивирусных сканеров.
- **AV/EDR suppression.** Подавление запросов на сброс и отключение антивирусного ПО — техника, направленная на нейтрализацию защитных решений до начала основной вредоносной активности.
- **Persistence.** Закрепление через автозагрузку и модификацию системных служб обеспечивает сохранение присутствия после перезагрузки.

**Аналитическая оценка:** SilverFox v1 представляет собой классический kernel rootkit, ориентированный на долгосрочное скрытое присутствие. Использование подписанного драйвера (или BYOVD-техники) для обхода Driver Signature Enforcement является характерной тенденцией современных rootkit-семейств.

### 4.2. SilverFox v2 (Trojan / Stealer, Critical)

**Класс угрозы:** Модифицированная версия семейства SilverFox с расширенным функционалом кражи данных и средств противодействия анализу.

**Ключевые техники:**
- **Anti-VM.** Определение виртуального окружения по артефактам гипервизора (VMware, VirtualBox, Hyper-V), MAC-адресам виртуальных сетевых адаптеров, наличию специфичных реестровых ключей. При обнаружении VM вредонос прекращает выполнение.
- **Anti-Analysis.** Детектирование запущенных инструментов реверс-инжиниринга и мониторинга: Process Monitor, x64dbg, Wireshark, IDA Pro. Реализуется через перечисление процессов и окон.
- **Windows Defender tampering.** Модификация реестра (`DisableAntiSpyware`) и групповых политик для отключения встроенного антивируса Windows.
- **DLL Hijacking.** Подмена легитимной DLL-библиотеки в директории Google Chrome (`chrome_elf.dll`) для выполнения вредоносного кода в контексте доверенного процесса.
- **Data exfiltration.** Кража паролей, cookie-сессий, персональных данных с последующей передачей на C2-сервер.

**Аналитическая оценка:** Эволюция от rootkit (v1) к полнофункциональному stealer (v2) демонстрирует типичный путь развития malware-семейств. Комбинация Anti-VM, Anti-Analysis и DLL Hijacking значительно усложняет статический и динамический анализ.

### 4.3. Kitty (Trojan, High)

**Класс угрозы:** Троян, распространяемый методом социальной инженерии под видом игрового ПО.

**Ключевые техники:**
- **Masquerading.** Маскировка под кастомный сервер Minecraft — эксплуатация доверия пользователей к игровому контенту.
- **Background execution.** Скрытая работа без видимого интерфейса, имитация легитимного серверного процесса.
- **Credential theft.** Извлечение сохранённых паролей из браузеров (Chrome, Firefox, Edge) через доступ к профилям и базам данных логинов.
- **Session hijacking.** Кража игровых сессий и токенов авторизации Minecraft для несанкционированного доступа к аккаунтам.

**Аналитическая оценка:** Kitty иллюстрирует распространённый вектор атаки через игровые сообщества. Молодая аудитория Minecraft-серверов является привлекательной мишенью из-за низкой осведомлённости о киберугрозах.

### 4.4. Sorry (Ransomware, High)

**Класс угрозы:** Программа-вымогатель, ориентированная на Linux-системы.

**Ключевые техники:**
- **Ransom note generation.** Массовое создание файлов WriteUp с инструкциями по оплате выкупа до начала шифрования — психологическое давление на жертву.
- **File encryption.** Рекурсивное шифрование пользовательских файлов алгоритмом AES-256 с добавлением расширения `.sorry`.
- **Backup destruction.** Удаление теневых копий и снимков файловой системы для предотвращения восстановления без уплаты выкупа.
- **Self-deletion.** Удаление исполняемого файла после завершения операции для затруднения форензик-анализа.

**Аналитическая оценка:** Sorry демонстрирует адаптацию ransomware-угроз под Linux-экосистему. Отсутствие реестра Windows в IoC (пустой список `registry`) корректно отражает целевую платформу.

### 4.5. DSCourier (Exploitation Tool, Critical)

**Класс угрозы:** Инструментарий для обхода механизмов защиты Windows, используемый на этапе постэксплуатации.

**Ключевые техники:**
- **DSE bypass (Driver Signature Enforcement).** Использование уязвимых, но легитимно подписанных драйверов (BYOVD — Bring Your Own Vulnerable Driver) для загрузки неподписанного кода в ядро.
- **CI subsystem exploitation.** Атака на подсистему Code Integrity, ответственную за проверку цифровых подписей исполняемых файлов и драйверов.
- **Kernel protections disabling.** Попытки отключения PatchGuard (защита критических структур ядра), SMEP и SMAP (защита от выполнения кода из пользовательского пространства в режиме ядра).

**Аналитическая оценка:** DSCourier относится к категории offensive security tools. Подобные инструменты активно используются APT-группами и red team-специалистами. Техника BYOVD стала одной из наиболее актуальных угроз для Windows-систем в 2023–2025 годах.

## 5. Контейнеризация

### 5.1. Dockerfile

Dockerfile описывает процесс сборки Docker-образа:

1. **Базовый образ:** `python:3.11-slim` — минимальный образ Python без лишних системных пакетов.
2. **Установка зависимостей:** Копирование `requirements.txt` и установка Flask и Gunicorn через pip.
3. **Копирование кода:** Все файлы проекта копируются в рабочую директорию `/app`.
4. **Экспорт порта:** Порт 5000 объявлен для внешнего доступа.
5. **Команда запуска:** Gunicorn с флагом `--reload` для автоматической перезагрузки при изменении исходного кода.

### 5.2. docker-compose.yml

Файл docker-compose определяет сервис `web`:

- **Сборка** из текущей директории (контекст `.`).
- **Проброс порта** `5000:5000` для доступа к приложению с хост-машины.
- **Volume mount** `./app:/app/app` — монтирование директории с исходным кодом для live-reload при разработке без пересборки образа.
- **Переменная окружения** `FLASK_ENV=development`.

### 5.3. Команды для сборки и развёртывания

**Сборка и запуск:**

```bash
docker-compose up --build
```

**Остановка:**

```bash
docker-compose down
```

**Проверка работоспособности:**

```bash
curl http://localhost:5000/
curl http://localhost:5000/api/v1/malware/kitty
```

После запуска приложение доступно в браузере по адресу `http://localhost:5000`.


## 6. Пользовательский интерфейс

Интерфейс разработан в стиле внутренней панели мониторинга антивирусной лаборатории:

- **Цветовая палитра:** тёмный фон `bg-zinc-900`, основной текст `text-zinc-100`, границы `border-zinc-800`.
- **Типографика:** моноширинный шрифт (`font-mono`) для хэшей, путей файлов и ключей реестра.
- **Индикаторы угроз:** матовые цветные плашки — `Critical` (красный), `High` (янтарный) — без неоновых эффектов и градиентов.
- **Структура:** главная страница — таблица образцов; детальная — описание, список механизмов, блок IoC.

## 7. Заключение

В ходе выполнения работы было разработано веб-приложение на Flask для демонстрации базы данных проанализированного вредоносного ПО. Приложение включает:

- каталог из 5 образцов malware различных классов (Rootkit, Trojan/Stealer, Trojan, Ransomware, Exploitation Tool);
- веб-интерфейс с табличным и детальным представлением данных;
- REST API для программного доступа к threat intelligence в формате JSON;
- Docker-контейнеризацию с поддержкой live-reload для удобства разработки.

Проведённый аналитический разбор пяти образцов (SilverFox v1/v2, Kitty, Sorry, DSCourier) демонстрирует разнообразие современных техник вредоносного ПО: от kernel-mode rootkit и BYOVD-эксплуатации до социальной инженерии через игровые платформы и ransomware для Linux.
